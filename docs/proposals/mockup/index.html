Full-text search on lakehouse tables, inside your query engine.

IndexTables writes search indexes next to your data in object storage. Apache Spark and Apache DataFusion query them directly, so there is no search cluster to run, feed or pay for.

Get started in 5 minutesExplain it to me simply
-- register an existing table, then search it
CREATE TABLE docs USING indextables
LOCATION 's3://my-bucket/docs';

SELECT id, title FROM docs
WHERE title indexquery 'quick fox'
  AND region = 'us';
df.write.format("indextables") \
  .option("spark.indextables.indexing.typemap.title", "text") \
  .partitionBy("region").mode("append") \
  .save("s3://my-bucket/docs")

docs = spark.read.format("indextables").load("s3://my-bucket/docs")
docs.where("title indexquery 'quick fox' AND region = 'us'") \
    .select("id", "title").show()

How it works

1

Write an index beside your data

A Spark write produces immutable index files, called splits, in your own bucket.

2

Commit it in a transaction log

Each write is one atomic commit. Readers always see a consistent snapshot.

3

Search from your engine

Spark executors, or a DataFusion process, open only the splits and bytes a query needs. No server sits in between.

Why IndexTables

Search without a second system

For people deciding whether this belongs in their platform.

Most teams that need text search over large data run a search cluster beside their lakehouse and copy data into it. That means two copies, two security models and a pipeline between them.

IndexTables keeps the index in your object storage, in an open table layout, and lets the engine you already run do the searching.

You wantGood fit?
Keyword and phrase search over logs, events or documents already in a lakehouseYes
Search combined with SQL joins and aggregates in one queryYes
An always-on search API serving end users at millisecond latencyNot the goal
Tables on HDFSNot supported

IndexTables in plain English

What an index is, where IndexTables keeps it, and why that saves you a cluster. Prefer to watch? See the 36-minute talk.

Imagine a thousand-page book with no index at the back. To find every mention of "invoice" you read every page. That is what a query engine does when it scans files for a word.

An inverted index is the index at the back of the book: for each word, the list of places it appears.

Where the index lives

A search server keeps its index on its own disks. IndexTables keeps it as ordinary files in the same bucket as your tables. Each file is called a split, and a small log records which splits make up the table right now.

Who does the searching

Your query engine does: Apache Spark, or Apache DataFusion inside your own program. It fetches just the parts of the splits a query needs. When the query ends, nothing is left running.

Get started / Quickstart

Quickstart

Your choice is remembered across the docs.
Foranyone with Spark 3.5 or 4.x and JDK 17. You willwrite a small table and run a text search, on your laptop.

  1. Start Spark with the extension

    val spark = SparkSession.builder()
  .master("local[2]")
  .config("spark.sql.extensions",
    "io.indextables.extensions.IndexTablesSparkExtensions")
  .getOrCreate()

  2. Write three rows

    Strings are indexed as exact values unless you ask for text. Here title becomes searchable text.

    documents.write.format("indextables")
  .option("spark.indextables.indexing.typemap.title", "text")
  .partitionBy("region").mode("append")
  .save("/tmp/indextables-example")

  3. Search

    spark.sql("SELECT id, title FROM a WHERE title indexquery 'fox'").show()
    # expected output, checked in CI
|  1| The quick brown fox |
|  2| quick fox jumps     |
    Two words mean both. 'quick fox' matches rows containing both terms. CORE-QRY-IQCORE-QRY-IQ · groupIndexQuery syntax and semantics. This page cites the whole group, so a new requirement added to it flags this page for review.core/query
ForRust developers using DataFusion. You willsearch an existing IndexTables table from your own process, with no JVM.

  1. Add the adapter

    cargo add indextables-datafusion

    Register the adapter on your SessionContext. That adds the INDEXTABLES table format and the indexquery functions.

  2. Point at a table

    CREATE EXTERNAL TABLE docs
STORED AS INDEXTABLES
LOCATION '/tmp/indextables-example';
    DataFusion reads tables. Creating and writing them is done from Spark today. Writes deferred

  3. Search

    SELECT id, title FROM docs
WHERE indexquery(title, 'fox');
    # expected output, checked in CI
|  1| The quick brown fox |
|  2| quick fox jumps     |
    Same answer as Spark. Both engines call the same core, and the project tests them against the same expected results. DF-AD-IQDF-AD-IQ · groupIndexQuery in DataFusion through the indexquery and indexqueryall functions.datafusion/adapter

Guides / Query / Read modes and limits   Spark

Choose a read mode

Foranalysts and engineers querying a table. You willknow when results are complete and how to make them so.

IndexTables has two read modes. Both return only correct rows. They differ in how many matching rows an interactive query brings back.

ModeReturnsUse it for
fast (default)Up to 250 matching rows for row-returning queries, and says when it stopped earlyExploring, dashboards, "show me some examples"
exactEvery matching rowExports, joins you will act on, anything you count by hand

Switch to exact

SET spark.indextables.read.mode = exact;
spark.read.format("indextables") \
  .option("spark.indextables.read.mode", "exact").load(root)
spark.read.format("indextables")
  .option("spark.indextables.read.mode", "exact").load(root)

What fast mode never limits

The limit applies to rows returned to you. It never shortens the input to a write, a cache, a join or an aggregate. SPARK-RD-MODESPARK-RD-MODE · groupRead modes and the fast-mode cap.spark/read · verified at upstream e947724

Using DataFusion? Fast mode is a Spark feature today. DataFusion queries return every matching row.
Why a default limit at all? See Concepts: exact, bounded, never approximate.

<p class="hero-h">Fast <mark>search</mark> and retrieval on lakehouse tables, inside your query engine.</p>

<p class="lede">Full-text search, exact match and range lookups, answered from an index instead of a scan. Store data in an IndexTables table, or add an index to the Delta, Iceberg or Parquet tables you already have. It runs inside Spark and DataFusion, on object storage, with no search cluster to operate.</p>

<p class="cta"><a class="primary" href="/start/spark/">Get started with Spark</a><a href="/start/datafusion/">Get started with DataFusion</a><a href="/learn/what-is-indextables/">What is IndexTables?</a></p>

One query, three kinds of match: words in a message, an exact value, and a time range.

<Tabs syncKey="lang">
<TabItem label="Spark SQL">
```sql
SELECT ts, service, message
FROM events
WHERE message indexquery 'connection AND (timeout OR refused)'
  AND user_id = 'u-48213'
  AND ts >= TIMESTAMP '2026-11-01 00:00:00';
```
</TabItem>
<TabItem label="PySpark">
```python
events = spark.read.format("indextables").load("s3://my-bucket/events")

(events
  .where("message indexquery 'connection AND (timeout OR refused)'")
  .where("user_id = 'u-48213' AND ts >= '2026-11-01'")
  .select("ts", "service", "message")
  .show())
```
</TabItem>
<TabItem label="Scala">
```scala

events
```

<TabItem label="DataFusion">
```sql
CREATE EXTERNAL TABLE events
STORED AS INDEXTABLES
LOCATION 's3://my-bucket/events';

SELECT ts, service, message
FROM events
WHERE indexquery(message, 'connection AND (timeout OR refused)')
  AND user_id = 'u-48213'
  AND ts >= TIMESTAMP '2026-11-01 00:00:00';
```

## What the index answers

<div class="grid c4">
<div>
<p class="k">Text search</p>

Words, phrases and boolean combinations in text columns.

`message indexquery '"disk full" OR quota'`
</div>
<div>
<p class="k">Exact match</p>

One ID among billions of rows, without reading the rest.

`trace_id = '7f3a…'`
</div>
<div>
<p class="k">Range</p>

A time window or a numeric band, pruned by file and then by index.

`ts BETWEEN … AND …`
</div>
<div>
<p class="k">Counts and totals</p>

`COUNT`, `SUM`, `MIN`, `MAX` and grouped results computed in the index.

`SELECT service, count(*) … GROUP BY service`
</div>
</div>

Ordinary SQL filters and aggregates are pushed to the index where it can answer them exactly. Where it cannot, the engine computes the result itself or the query is refused, according to a policy you set. See [filters](/guides/query/filters/) and [aggregates](/guides/query/aggregates/).

## How it works

<div class="grid c3 steps3">
<div>
### Write a table, or index one
Write a DataFrame with `format("indextables")`, or run `BUILD INDEXTABLES COMPANION` over an existing Delta, Iceberg or Parquet table.
</div>
<div>
### The index lives in object storage
Immutable index files and a transaction log sit under one path on S3, Azure, GCS or local disk. There is no server to run.
</div>
<div>
### Your engine reads it directly
Spark executors or DataFusion partitions open the index files they need, cache them locally, and return rows or aggregates.
</div>
</div>

<div class="grid c2">
<div>
### Standalone table
The index is the table. IndexTables stores the rows and the index together, and you read and write it like any other Spark data source.

[Create a standalone table](/guides/tables/write/)
</div>
<div>
### Companion table
An index over a table you already have. Rows stay in your Delta, Iceberg or Parquet files; the companion holds the index and keeps up with the source through incremental sync.

[Build a companion](/guides/companions/overview/)
</div>
</div>

## What works today

IndexTables is being rebuilt from written requirements, and every page here is checked against them. The [availability matrix](/reference/availability/) is computed from those requirements, so it says what is implemented, not what is planned.

<div class="grid c3">
<div>
<p class="k">Engines</p>

Spark 3.5 and 4.2, Spark Connect, and a DataFusion adapter for Rust.
</div>
<div>
<p class="k">Storage</p>

Local disk and S3-compatible storage for reads and writes. Azure and GCS for reads; writes there are planned.
</div>
<div>
<p class="k">Sources</p>

Companions over Parquet directories, Delta tables and Iceberg tables, with row-level deletes honoured.
</div>
